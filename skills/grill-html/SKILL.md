# grill-html

This is the **grilling** skill with an HTML page as the question surface. Read and follow `~/.agents/skills/grilling/SKILL.md` first: design tree, frontier rounds, recommendations worded so "yes" accepts them, facts researched using available tools or authorized subagents, decisions left to the owner, and the confirmed session record at the end. Everything below only replaces *where* questions are asked and answered.

## Files

- State: `<topic dir>/grill/state.json`. It is the source of truth. Never hand-edit the grill HTML.
- Render: `python3 ~/.agents/skills/grill-html/render.py <topic dir>/grill/state.json` (prints `<page>#grilling-session` and the agreement %).
- **One page, not two.** If the topic already has an explainer page (a plan page, report or audit page), embed the grill in it: set `"host"` in state.json to that page (path relative to state.json) and `"host_after"` to the section id it should follow. The grill becomes `<section id="grilling-session">` between `<!-- grill-html:start/end -->` markers, replaced on each render, so the owner reads the project and answers in one place. Set `"host_rounds"` to rounds the host already shows in full, so they are not repeated. Host answer boxes `textarea.owe` (data-q, data-title, data-orig) are copied as CHANGE lines.
- If the host page is generated by a build script, add a final step to that script that re-runs render.py, so a rebuild keeps the grill (for example, the project page builder).
- No explainer page yet: leave out `host`; render.py writes a standalone `<topic dir>/grill.html` using `assets/theme.css` (the bundled page theme). Put the project explanation in `explainer` sections.
- Look: the template reuses the bundled theme (cards `.qc/.qi/.ans`, `.facts`, `.chart`, `.note`, `.legend`, `details.more`, meter classes `meter/meterfill/tgt`). Keep new styles inside `#grilling-session`.
- If the topic is a plan, add a button for the page to that plan's `index.html` in the same turn.
- Archive, never delete: before a big state rewrite, `mv` the old copy into `grill/_archive/`.

## state.json

```json
{
  "slug": "dev-cycle-tiers", "title": "Plain page title", "short_title": "2-4 word tab title",
  "plan": "example-project", "host": "../../overview.html", "host_after": "grill", "host_rounds": [1], "goal": "One sentence: what we are deciding and why.",
  "updated": "YYYY-MM-DD", "target": 95, "round": 2, "status": "grilling | confirm | done",
  "round_intro": "Optional line above this round's questions.",
  "tree": [{"id": "B1", "label": "Budget: what pauses a run", "status": "settled|open|assumed|out", "note": "D18"}],
  "explainer": [{"id": "budget", "title": "How budgets work", "sub": "one line", "icon": "list", "html": "<p>...</p><svg ...>"}],
  "rounds": [{"n": 1, "status": "answered", "date": "YYYY-MM-DD", "questions": [
     {"id": "Q1", "title": "Question?", "plain": "Why it matters, plain words.", "rec": "Yes. ...",
      "options": ["optional alternative A", "B"], "answer": "owner's words", "kind": "y|c", "decisions": "D03"}]},
     {"n": 2, "status": "open", "clarifications": [{"title": "You asked", "text": "..."}], "questions": [ ... no answer yet ... ]}],
  "decisions": [{"id": "D01", "text": "..."}],
  "transcript": [{"who": "Owner|Agent", "text": "..."}]
}
```

- Exactly one round may have `"status": "open"`: the round waiting on the owner.
- `kind`: `y` = answered as recommended, `c` = the owner changed it.
- `answer` holds the owner's words verbatim (plus the option text when they picked one).
- Agreement % = settled ÷ (all tree branches except `out`). Mark a branch `assumed` when you are relying on something not yet asked. Do not inflate the % by leaving branches out of the tree.
- `icon` values: q, ok, chg, tree, copy, flag, list, chat, wait.

## Explainer sections (the teaching part)

## Browser tab icon

Every grill page gets an SVG favicon: a teal line icon on a dark rounded tile, built by render.py from the icon set. Set `"favicon"` in state.json to an icon name that fits the topic (default `q`). Host pages that already have `rel="icon"` keep their own.

## Section rubric (every new or updated section and question, each round)

Apply this to every explainer and question added or changed in any round, not only the first:

1. **Icon on every section.** Set `icon` (q, ok, chg, tree, copy, flag, list, chat, wait, coin, bolt, wrench, shield, search, chip, db, plug, star). Table headers may carry icons too: `["Cost", "coin"]`.
2. **Beautiful tables, not raw `<table>` HTML.** Use `blocks` with `{"type":"table","cols":[...],"rows":[...],"pick":[row index of the recommendation],"caption":"..."}`. Cells are visual: `{"t":"$0","tone":"ok|wr|bad"}` (pill), `{"dots":1-5,"tone":"wr"}` (rating), `{"bar":0-100,"t":"label"}` (mini bar). Rate with pills and dots, not sentences.
3. **At least one graphic per section.** Use `{"type":"bars","title":"...","rows":[[label, value, shown, "wr"?]]}` (animated bars), `{"type":"cards","items":[{"icon","title","text"}]}` (fade-in cards), or an inline SVG in `html`. Motion stays subtle; render.py disables it under prefers-reduced-motion.
4. **Plain words, fewer words.** Write for a non-technical owner. One idea per sentence, at most about 15 words, no jargon (or explain it in 3 words). Cut anything a pill, dot or bar already says. Question `plain` text: 2 short sentences at most. `rec`: one line.
5. **Proposals and estimates are labelled** ("est.") and never shown as facts.

Other blocks: `{"type":"note","text":...}`, `{"type":"p","text":...}`; `html` still works for custom SVG.

**Compact after round 1:** give each explainer `"round": N` (the round it was added for; default 1). From round 2 on, render.py folds the design tree and every explainer from an earlier round into closed panels above the questions, so the owner reads only the new material and the open questions. Tag new explainers with the current round so they stay open. If an old explainer changes materially, bump its `round` so it reappears.

Write `explainer` sections so a non-expert owner can answer well: one per topic in the frontier, in plain words (short sentences, no jargon, "the owner" not names). Each should include at least one inline SVG: a flow, a comparison, a timeline or a small chart. Wrap each SVG in `<figure class="chart">`. Use the bundled SVG classes (`st`, `ss`, `sh`, `bx ok|wr`) or the page's classes `s-t`, `s-m`, `s-n` (text), `s-fill`, `s-wr`, `s-dim`, `s-trk` (fills). Give each SVG a `viewBox`, `role="img"` and a `<title>`, and keep it legible at phone width. Wrap a callout in `<div class="note">`. Update explainers as decisions land. Never invent facts: mark proposals as proposals.

## Loop

1. **Start:** build the design tree, write the explainers, put round 1 (the whole frontier) in as the open round, render, add the index button. Reply in at most 3 lines plus the page path lines (using the project's output conventions), with `#grilling-session` appended to the localhost URL so it opens on the open questions: "Round N is on the page. Answer, press Copy answers, paste here."
2. **Owner pastes** (no need to call the skill again; the block's first line names the state file) a block starting `GRILL-HTML ANSWERS v1` and ending `END`. For each `Qn`:
   - `answer: yes` → record the recommendation as the answer, `kind: y`.
   - `answer: A: <text>` / `other: <text>` → record it, `kind: c`; a `note:` line is added to the answer.
   - `(skipped)` → leave it unanswered and carry it into the next round.
   - `CHANGE Qn` lines → replace that earlier answer, set `kind: c`, revisit every branch that depended on it, and note this in the next round's `clarifications`.
   - `GENERAL:` → treat it as owner input. Ask about it if it is unclear.
   If something is ambiguous, ask about it as a clarification question in the next round, not in the chat.
3. **Update:** the page shows only the remaining (open) questions in full; answered rounds render as closed, one-line rows under "The full grilling session" (click to expand). Do not repeat answered questions in the open round. Close the round (`answered`), update the tree, decisions and explainers, compute the new frontier, add it as the next open round, bump `round`, render to the same path. Same short reply.
4. **Plain chat answers also count.** If the owner answers in chat instead, record those answers the same way.
5. **95% gate:** when agreement ≥ target and the frontier is empty, set `status: confirm` and make the final open round one question: "Have we reached a shared understanding? (Yes = hand off.)" with any remaining assumed branches listed. Only the owner's yes ends the session. Never auto-finish.
6. **Done:** set `status: done` with a `done_note`, render, then write the grilling skill's confirmed session record in the selected project. Link `grill.html` from the record.

Copy button: render.py copies with a direct copy first, then the clipboard API, then leaves the block selected in the preview box for Ctrl+C. If the owner says copy fails, check for a stuck xclip (`ps -eo stat,comm | grep xclip`, state T) before changing the page.

If the environment provides a notification tool, optionally notify the user that the next round is ready.
